## Git Words, Cartenza Words, and Who Is Conducting

Cartenza keeps your knowledge in Git, which is the right choice for something you should own forever — but it means the product borrows a handful of words from a tool you may never have used. This is the translation.

**You do not need to learn Git to use Cartenza.** Everything below is already done for you by a button or by your agent. This exists so that when you or your agent says "push" and the screen says "Refresh", you both know those are different things.

### The words, and where you meet them

| Git calls it | Cartenza calls it | What it actually means |
|---|---|---|
| repository | **notebook**, or just a repo | The folder of knowledge you own. One notebook, one repo. |
| clone | **verify**, or connecting a repo | Cartenza takes its own copy of your notebook so it can read and show it. |
| pull | **↻ Refresh** | Fetch anything that changed elsewhere — another device, a teammate, an agent — into the copy you're looking at. |
| commit | *(nothing — it just happens)* | Every entry you write is saved as its own permanent, dated record. You never do this by hand. |
| push | *(nothing — it just happens)* | Sending those records to GitHub, where they actually live. Cartenza does it and tells you when it worked. |
| fresh clone | **⟳ Reclone** | Throw the local copy away and take a new one. The repair when a copy has gone strange; your knowledge on GitHub is untouched. |
| branch | **branch** | A parallel version of a notebook. Most people only ever use one — usually `main`, or `master` on Capella models. |
| — | **package** | A folder of related entries inside one notebook. Cartenza's own idea, not a Git one. |

**Two of these are worth remembering**, because they are where confusion usually starts:

- **Refresh pulls; it does not send.** If you wrote something elsewhere and don't see it, Refresh. If you wrote something *here*, it's already saved and sent — Refresh won't help.
- **Reclone throws away the local copy, not your knowledge.** It reads like a destructive button. It isn't: everything lives on GitHub, and Reclone just fetches it again.

### Your Repos & Agents: the conductor's view

This is the page where you see everything at once — your notebooks, your agents, and what each agent can reach. It is the one place you decide who plays what.

Cartenza's own framing is an orchestra: **you conduct, your agents play.** The page is your score.

- **Your repos** — the notebooks you own. A repo shows **● verified** when Cartenza currently holds a working copy and can show it to you, and **○ not verified** when it doesn't yet. That's about *this browser session*, not about your agents.
- **Your agents** — the assistants you've registered. Each one has a name, an id, and a system prompt written for it.
- **A scope** — one line granting one agent access to one notebook, on one branch, to read or to write. **Scope is the part you conduct.** An agent can only reach what you have scoped to it: nothing else in your account, and nothing belonging to anyone else. Adding a scope is handing a player their part; removing it takes the part back.

### What the status beside a scope means

Each scope says what it would **cost you** for that agent to open that notebook — not whether it has done so before:

- **● ready** — you connected that notebook with **Connect via GitHub**, so the agent can open it with no interruption to you at all.
- **● reference** — shared public material, like this handbook. No credential needed by anyone.
- **○ needs GitHub** — not connected yet, or connected by pasting a token. The next session will stop and ask you to authorize once in a browser.

**"needs GitHub" is not an error.** It's a price tag: one browser trip, once, and then that notebook becomes **ready** and stays that way.

### Why "Connect via GitHub" is worth choosing

When you authorize a notebook, you're offered two ways: connect with GitHub, or paste a personal access token. **Choose GitHub.** It covers your other repositories too, so a Capella model's library repos need nothing further — and it *persists*, so later sessions resume without asking you again. A pasted token is a single-use snapshot: it works now, and the next session sends you back to the browser.

### If you only remember four things

1. **Your knowledge lives on GitHub, in your account.** Cartenza works on a copy.
2. **Refresh pulls changes in.** Writing already saves and sends.
3. **A scope is what an agent may reach.** You grant it, you remove it.
4. **"Connect via GitHub" once beats pasting a token every time.**

**Reference:** the connecting entry in this package (what happens when you authorize, and why it costs a browser trip), the entries on packages and entry ids (how a notebook is organized inside).
