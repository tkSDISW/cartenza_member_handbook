## Entry IDs: What the Prefix Means, and Where the Number Comes From

Every entry gets an id like `obs-0004-8807d4ab1c644fc5…`: a **prefix**, a **number**, and a uuid that makes the filename unique. You'll see the first two together as a short label — **OBS-0004** — in the viewer, in search results, and whenever anyone refers to an entry in conversation.

Two questions come up constantly, and the answers aren't obvious from looking at a package.

### The prefix comes from a fixed list, not a rule

These types have their own prefix:

| Prefix | Type |
|---|---|
| `obs-` | observation |
| `dec-` | decision |
| `lesson-` | lesson_learned |
| `routine-` | routine_def |
| `bcfg-` | behavior_config |
| `nbcfg-` | notebook_config |
| `ncfg-` `dcfg-` `ocfg-` `lcfg-` | the `{type}_configuration` singletons |

**Everything else gets `note-`.** Not because it's a lesser kind of entry — because the list is an explicit allowlist, and anything not on it falls back. So `note`, `purpose`, `issue` and `milestone` entries all carry `note-` ids, which is why a `purpose` entry looks like `note-0004` and an issue can look like `note-0107`.

**The consequence worth knowing: `note-` is one shared sequence across all those types.** A package's notes, issues, milestones and purpose entry are numbered together in one run, not separately. The four types with their own prefix each get their own run.

### The number is per package, per prefix

**Numbering restarts in every package.** `dec-0001` in one package and `dec-0001` in another are two unrelated entries, both correct. A repo has no single sequence.

So **an entry id only identifies an entry when you say which package it's in.** Write `release_trains/dec-0001`, not `dec-0001`, whenever there's any chance of ambiguity — and there usually is.

A new entry takes **one past the highest number already used** by its prefix in that package. Two things follow:

- **Gaps are permanent.** Delete an entry and its number is retired; the next entry continues past the highest, it doesn't backfill the hole. A gap means something was deleted, which is worth knowing when a sequence looks odd.
- **A number is never reused**, so a label like OBS-0004 keeps meaning one entry for the life of the package.

### Referring to an entry you're about to create

**Write the entry first, then cite the id it actually got.** You cannot predict the next number: another session may be writing to the same package at the same moment, and the answer depends on what's already there. Citing an id in advance and creating the entry afterwards is how two different things end up wearing the same number in people's notes — the id was taken in between.

The same applies to entries that cite each other: create the one being cited first, read back its real id, then write the citation.
