## capella-fabric: What It Is and How to Connect

**capella-fabric is access to a Capella model, not a place to log.** It reads and changes the model itself: the operational, system, logical and physical layers, requirements, data modeling, and diagrams. It does **not** record notes, observations or decisions about that work. Those go to `knowledge-repo` through `add_log_entry`, which is a separate server with its own session. Mixing the two up is an easy mistake that has happened for real, so check which server a task belongs to before calling anything.

### New to Capella?

This handbook covers Cartenza, not Capella modeling itself. To learn Capella and the Arcadia method it's built on, **[Innovating with Capella](https://www.youtube.com/@innovatingwithcapella)** on YouTube walks through real modeling work, and Capella's own documentation covers the tool in depth.

### Connecting

Your model lives in a private git repository, and the agent never handles your credential.

**If the model repo has been connected with GitHub before, try this first:**

```
clone_capella_repo(repo_url=<model repo>, agent_id=AGENT_ID)
```

No credential, no connect code, no browser trip — it reuses the authorization the owner already gave for a repo in the agent's scope. If there's nothing stored to reuse, the error says what the human has to do, and you fall back to the flow below.

**For a first connection**, the flow is the one described in `getting_started`'s "Connecting to a Repo", with two capella-specific details:

```
begin_connect(agent_id=AGENT_ID, repo_url=<model repo>, branch=<branch>)
```

→ print the returned `connect_url` for the user → they authorize in a browser →

```
clone_capella_repo(connect_code=<code>)
```

- **The argument is `repo_url` here, not `remote_url`.** knowledge-repo's `begin_connect` uses `remote_url`; capella-fabric's uses `repo_url`. Going by memory from the other server gets this wrong.
- **The branch has to match what the agent is scoped to.** Capella model repos commonly use `master` rather than `main`, and the scope check compares branches exactly. If `begin_connect` refuses a repo you know is registered, check the branch before anything else.

### "Connect with GitHub" matters most here

On the connect page, the user can either authorize with GitHub or paste a personal access token. **For Capella, GitHub is much better.**

Models often depend on **library repositories**: shared component or data libraries referenced from the main model. Each has to be added to the session with `add_dependency_repo` before browsing.

- **With GitHub authorization**, one authorization covers the user's other repositories too, so `add_dependency_repo` needs no credential at all.
- **With a pasted token**, the token is a single-use snapshot, so every library repo needs its own connect link and its own trip to the browser.

A model with three libraries is one browser trip versus four.

**And it lasts.** A GitHub authorization stays available afterwards, so resuming this model tomorrow costs nothing at all. A pasted token doesn't survive the session it was used for.

### Sessions

A session is a handle to a server-side copy of the model, and it doesn't last forever:

- Sessions are swept about **4 hours after last use**, and are gone after a server restart. You'll see "Unknown session_id".
- **Resuming is usually free.** Call `clone_capella_repo(repo_url=..., agent_id=...)` with no credential: for a model repo in your scope that its owner connected with "Connect with GitHub", it reuses that authorization. It's a **PAT-linked repo, or one never connected with GitHub, that costs a fresh browser trip** — so still batch model work into one session rather than cloning between every step.
- **Don't call `cleanup_session` unless the user says they're finished.** A live session costs nothing to leave open, and a model session may be holding committed work that hasn't been pushed yet.
- **Keep using the `session_id` you're holding.** Re-cloning re-reads the whole model; the handle you already have costs nothing.

### If a clone fails

**A failed clone does not use up the connect code.** The code is consumed only when a clone succeeds. If `clone_capella_repo` fails because of a wrong branch, an empty repo, or no `.aird` model file found, fix the cause and **retry with the same code**. The error message says so. Ask the user for a new link only if the code has genuinely lapsed: 4 hours to authorize, then 1 hour to redeem.
